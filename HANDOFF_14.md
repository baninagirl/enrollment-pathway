# Kumon Hub: handoff note

Paste this into a fresh Claude chat along with the project files. It is the whole memory of the project.

## What this is
A static website (plain HTML, no build step) for the Kumon Iligan City Learning Center, backed by Supabase (Postgres, row-level security, login). Hosted on Vercel. Live data is in the Supabase project named **Enrollment Hub** (address starts with `bcnmsryahczapnxbpkve`). Do not point this at the old Kumon 2 project.

## Pages
- `index.html`: Pipeline (diagnostic tests), DT & Training, Enrollment, Weekly view, New students, Settings. Also has the slot finders (Generate DT slots, Available training slots).
- `roster.html`: roster, reporting tags, add student.
- `calendar.html`: calendar, with links into the slot finders.
- `payments.html`: payments, billing groups, SOA images, Log a payment, Mark absent.
- `absent.html`: absence tracking and catch-up/resume.
- `admin.html`: team accounts and roles. `activity.html`: edit history. `reporting.html` (stub). `history.html` was removed (unused, nothing linked to it).
- Helper code is duplicated in each file, so a shared change usually has to be made in several pages.

## How data works
- `students`: one row per child. `subject_enrollments`: one row per subject per student, with its own teacher. `schedules`, `diagnostics`, `trainings`, `payment_receipts`, `billing_groups`, `absence_records`, `enrollment_monthly_history`, `settings` (staff lists).
- Roles: admin, superadmin, teacher, trainer_teacher, pending. A teacher only sees enrollments where `subject_enrollments.teacher` exactly equals her profile's `teacher_name`. Spelling must match exactly.
- Receipts are saved against the student and month, not the teacher. Tuition per subject; grade 7 and up is a fixed 2,350 per subject (client rule plus a database trigger).
- Roster/report cycle runs the 21st to the 20th, named by the month that holds the 20th.
- Open month (phase38): `settings` row id `open_month`, value `{"key":"YYYY-MM"}`. Student Roster's editable month comes from it, not the date, and it only advances when an admin clicks Close out (undo moves it back). NEW label and monitor start month for newly added students still use the date-based month, so someone added Oct 21+ while October is still open gets NEW · November; they're left out of the October report and close-out (`joinsLaterMonth`). NEW labels show while their month is >= the open month.
- Staff (Pipeline → Settings): one Staff table, a row per person with Teacher / Trainer / DT teacher checkboxes and Remove. Stored in `settings` row `staff` as three lists: `teachers` (new; Math/Reading teacher pickers, Add subject, Move to regular, roster/payments/calendar/history teacher filters), `trainers` (training booking, monitoring trainer, slot finder), `examiners` (DT booking). Until `teachers` is saved once, every page falls back to `trainers`. Admin's New login / teacher name adds the name to Teachers (and Trainers for Trainer + Teacher). Removing a name never changes students already under it. No SQL needed.
- Multi-pick filters (shared `mp` component, copied into calendar.html and roster.html: MP registry, mpHtml/mpRender/mpSet; none ticked = all). Calendar: Teachers, Group, Level all multi-pick + Mode, stacking; picks remembered per browser (localStorage kumonCalTeachers/Groups/Levels). Calendar chips show the level tag. Student Roster and Report each have a Level multi-pick (options = levels in view with counts, plus "No level yet"); levels matched by exact code (Math D ≠ Reading DI). Teacher accounts don't see the Teachers picker.
- Slot finder (index.html, Generate DT slots / Available training slots): "Save as image" downloads a JPEG of the open slots for the week shown (saveSlotImage; open times only, past/full left out).
- Teachers can + Add to roster (roster.html): teacher is locked to their own name, monitor box unticked by default for plain teachers, and before adding a subject to an existing student it calls subject_taken_by (phase66) to block a duplicate.
- Mark paid (payments.html): per-row button when anything is left this month; inserts one receipt for the remaining per-subject amount, reference "Marked paid (no receipt)". Superadmin → verified right away (reviewed_by/at set); everyone else → pending for review. Undo via the 🕘 payment history.
- Reports page (reports.html, superadmin only; nav link "Reports" on every page, hidden for other roles): live from subject_enrollments (active) + students + schedules, paged past 1000 rows. Filters: Teachers + Level groups (multi-pick, remembered per browser), Subject, Mode. KPI tiles, donuts (level groups — click to filter; Math vs Reading; Paper vs KC), per-level column charts (Math, Reading, coloured by group), by-teacher table with group stacked bars (click row to toggle teacher), students per grade, Needs attention (no level / not on Calendar / same subject twice). Chart colours = validated dataviz palette.
- Supabase API "Max rows" raised from 1000 to 10000 (Nina, Oct 18 2026) — pages load whole tables in one select (roster sorts enrollments by name), so at 1000 the alphabetically-last rows silently dropped. reports.html pages through with .range() regardless. If tables grow past 10000, add paging to roster/calendar/payments/index loads.
- Billing is calendar months (`covers_month` = 1st of the month). Due on the 25th of the month before. Payments (and Student Roster's Payment tag) open on NEXT month's tuition all month long (Nina, Oct 2026): in October the SOA is for November, due Oct 25. But everything on screen is LABELLED by the report month (Nina: "this is the OCTOBER report"): month nav, table title, Log payment's Month field, last-paid/absent labels all say October; `reportYm()`/`fmtBillLabel()` in payments.html shift the label back one month, and Log payment shifts the field forward one month when saving, so `covers_month` stays the tuition month (2026-11-01). The SOA image is the exception: "For the Period" is the tuition month (November 1–30), due Oct 25. Student Roster's report column is just "Paid". Retention (absent.html) still labels by tuition month. Overdue flag after the 10th of the covered month. Billing does NOT move to the 21st–20th cycle.
- Payment subjects (phase39): `payment_receipts.allocation` jsonb, e.g. {"Math":2200,"Reading":2200}; required and must add up to amount (check constraint, `receipt_allocation_total`). Log payment (Payments and Retention) has one amount box per subject, pre-filled with what's left for that subject. Old receipts were split evenly across the student's subjects at migration. Paid/Partial/Unpaid still uses the whole student's total, for teachers too (Nina's choice); the split is there for per-subject absences next.
- Teacher scope on Payments (phase40 + payments.html `isMyStudent`): teacher/trainer_teacher only see, log and delete payments for students with a subject under their teacher_name (`teaches_student()`); review queue, Log payment list and payment history follow that. Billing groups are open to teachers too (member picker lists every student; saved through `set_billing_group_members`, which only touches billing_group_id). The SOA image gets every member's active subjects and verified payments from `billing_summary()` (security definer; teachers get their students plus anyone in the same billing group), so a family SOA has all siblings and one total whoever teaches them. Retention never falls back to all teachers for a teacher account.
- Payments: anyone with Payments access can log a payment (it starts "pending"). Only a **superadmin** can Verify, Flag or Reject (phase32, enforced in the database). Non-superadmins can delete only entries still pending; reviewed ones only a superadmin can remove.
- Reporting tags live in `enrollment_type`: new, eo, resume, new_returnee, resume_transfer_in. On Student Roster the tag is only shown and edited in the Report view (Tag column + report Edit modal); the Roster and Monitor views, their Edit/Add/bulk-edit forms no longer show it. Add to roster sets it automatically (NEW, or EO if the student already has a subject).
- Monitor (phase33): `subject_enrollments.is_monitor` alone decides it, and it stays on until someone moves the student off (Move to regular roster, unticking Monitor in roster Edit, or changing Pipeline status away from On monitor schedule). `monitor_since` ('YYYY-MM') = month it started, shown as "Monitor · <month>". `monitor_cycle` is now only the NEW label month. Pipeline's student status follows the flags both ways (roster.html `syncPipelineMonitorStatus`, index.html `reconcileReadiness`), for Pipeline students only (origin ≠ 'roster'). Teachers can toggle monitor on their own students; `promote_monitor_enrollment` now allows teacher as well as trainer_teacher.
- Students are matched by exact lowercase name, not an ID. This causes duplicate risk.
- Names: `rename_student(student_id, first, last)` (phase35, security definer) updates students and every table with student_id + student_name. Admin any student; teacher/trainer_teacher only students with a subject under her teacher_name. Used by roster Edit enrollment (First/Last name fields) and Pipeline's Edit student.
- Merging: `merge_students(keep, drop)` (phase36, admin only; also runs from the SQL Editor) repoints every foreign key to students, fills keeper's blank details, copies the name, deletes drop. No UI yet.
